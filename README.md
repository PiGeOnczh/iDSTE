# iDSTE 战略经营管理系统

面向管理层、战略 PMO、业务单元与职能部门，贯通战略制定、年度经营、执行和复盘。首期验证同一项市场机会能否一路追溯到经营结果与纠偏责任。

## 六个业务模块

| 模块 | 完整范围 | 首期交付 |
| --- | --- | --- |
| 战略洞察 | 五看三定、客户访谈、市场与竞争分析、机会评估、AI 报告 | 录入证据和机会，记录来源、日期及事实、判断或假设 |
| 战略规划 | 业绩与机会双差、战略意图、H1/H2/H3 创新组合、业务设计、风险与收入预测 | 从机会建立战略目标，填写差距、目标值和责任组织 |
| 战略解码 | 公司至业务单元与部门的目标分解、KPI、战略举措 | 建立目标下的 KPI 和举措，明确责任人与考核周期 |
| 年度经营计划 | BP、年度任务、预算与资源配置 | 将举措纳入指定组织和财年的 BP，登记预算与币种 |
| 战略执行 | 项目组合、三级计划、任务令和里程碑 | 从 BP 条目建项目，记录负责人、里程碑与完成状态 |
| 经营复盘 | 月度经营分析、季度战略审视、差距及纠偏 | 登记 KPI 实际值，显示偏差，分派纠偏任务并跟踪关闭 |

## 首轮演示及验收

以虚构的海外减振器业务为例，从客户访谈证据建立机会，关联收入目标、KPI 和客户验证举措。在年度 BP 登记验证预算，建立项目和样件交付里程碑。月度复盘录入实际值并生成纠偏任务。重新打开记录后，PMO 能从纠偏任务回溯到目标与原始证据。

- 同一 KPI、组织及统计期间只有一条有效实际值。目标与实际采用同一单位和统计口径。
- KPI 存储目标方向。差异显示原值并标明是否达标，覆盖收入等越高越好和成本等越低越好的指标。
- 纠偏任务记录责任人、截止日期和关闭说明。已被引用的记录采用归档，既有追溯链接继续可用。
- 使用演示数据验收。真实业务数据接入前完成组织级访问控制和变更审计验证。

## 初始技术方案

暂定 TypeScript Web 应用、REST API 和 PostgreSQL，采用模块化单体。六个业务模块共享组织、成员、财年及审计能力。以数据库外键关联证据、机会、目标、举措、BP 条目、项目和复盘记录。KPI 实际值按指标与期间关联，预算采用定点数并明确币种。AI 洞察在人工录入流程跑通后接入，生成内容作为可编辑草稿并保留证据引用。

## 开发顺序

1. 初始化本地应用与数据库迁移，建立演示组织和财年。交付证据 → 机会 → 目标的首个可运行切片，验证新增、编辑、持久化和回溯。
2. 接上 KPI、举措、BP 条目、项目与里程碑，跑通预算及执行责任流转。
3. 加入实际值、经营偏差和纠偏任务，按演示场景验收闭环。
4. 完善审批、组织权限、历史版本与审计；随后扩展 AI 洞察、报表和外部系统集成。
